## 目标

提案对运行时的要求来自静态阅读，没有一条运行过。本子任务在真运行时上回答节点适配器（000-6）开工前必须知道的事，并把结果写成适配器可以直接照做的规则。

它是运行时接入的硬闸门：结论出来之前 000-6 不开工，000-1 里与运行时有关的定义也不冻结。带 KVM 的机器除了总体计划里列的要求，还要求宿主页大小是 4 KiB。

## 实验

带“补充”的是运行时调研提出、提案的实验清单里没有的；其余编号是提案的编号。

**可以在开发机做，不需要 KVM。**

| 实验 | 目的 | 通过标准 |
|---|---|---|
| 补充一：配置片段的静态校验 | 确认适配器该往 conductor 的配置里写什么。用 `node-ctl config conductor --resolve` 分别校验：sandbox-pool 式的片段；把容量写成 0 的片段；按显式资源池重写的片段；关闭超分的片段（D15） | 前两者按预期失败并记下错误文本；后两者通过，解析结果里的可分配量等于目标值 |
| 补充六：假运行时的来源 | 评估 kuasar 自带的不起虚拟机的桩能否脱离它的集群控制面单独使用 | 给出结论：用它，还是自己写一个最小的假运行时 |

**需要带 KVM 的机器。**

| 实验 | 目的 | 通过标准 |
|---|---|---|
| 环境验收 | 原样跑上游快速开始的七步：创建、等到运行、取执行令牌、执行命令、删除 | 命令的输出取回，沙箱被删除 |
| 凭据的制备 | 记下运行时的 API key、Manifest 密钥、加密密钥各自怎样生成、放在哪里、谁读它 | 步骤可重复；节点适配器需要读哪些文件有明确清单 |
| NE-1 与补充三：外部预算与容量拒绝的判据 | 关闭超分（D15），把池设小，连续创建直到不成功。记录 HTTP 状态码、状态的序列与耗时、执行结果字段、池状态命令的输出、conductor 日志里的失败阶段、已有沙箱是否被暂停。再用默认的超分做一遍作对照 | 池的大小等于写入值；给出拒绝的判据、总耗时的上限、已有沙箱的行为；关闭超分时已有沙箱不被暂停 |
| 补充四：建池时的重启语义 | 带着零个沙箱、一个运行中的沙箱、一个在途的创建，分别重启 conductor；重启前打开排空 | 运行中的沙箱存活；在途创建的结局确定；确认排空在重启后是否复位 |
| NE-3：经本地接口创建、查询、删除 | 用调用方指定的标识创建；重复创建；删除后再查询；订阅能否连上并收到全量和增量 | 幂等与冲突的行为记录下来；给出第一版用轮询是否足够的结论 |
| 补充二：节点栈与 Kubernetes 节点怎样共存 | 各试一次：上游的系统容器与 Kind 节点并列；原生服务装进 Kind 节点；单节点集群上的宿主机服务 | 选出一种可以作为正式验证形态的做法，见下 |
| 准备模板 | 做出第一个可用的模板，步骤可重复 | 用它能创建沙箱并执行命令 |

**共存实验的判定。** “接口可调用、可回读、可重启”还不够。系统容器与 Kind 节点并列只能证明逻辑链路，不能作为第一版 V1-4 的正式证据。正式的形态要满足：

- microVM 的进程在池所在的 Kubernetes 节点上，记下进程与 cgroup 的路径；
- 从 WorkloadManager 的 Pod 能连到节点适配器的监听地址；
- 适配器能读池状态，能重启 conductor 而不影响运行中的 microVM；
- 占位 Pod 的 requests、运行时实例外层的 CPU 与内存上限、运行时管理进程的开销，三者的关系写清楚，并给出池的大小该留多少余量。

**闸门的出口。** 拒绝的判据可靠，000-6 按它实现。判据不可靠时不能把拒绝报成“启动失败”就算过，要把情况报给负责人，在三条出路里选：降低 V1-5、请上游补接口、更换运行时。

**可选的对冲。** 要先得到负责人同意，并且只在另一台与开发机同规格、可丢弃的虚拟机上做，不在开发机做。

| 实验 | 目的 | 通过标准 |
|---|---|---|
| E0 | 这类机器上 PVM 的宿主内核能否起来 | 重启后可登录；`/dev/kvm` 存在；内核日志没有 PVM 相关的错误；Docker 和 Kind 仍可用 |
| E1 | 这类机器上 CubeSandbox 加 PVM 能否创建沙箱并执行命令 | 创建、执行、暂停、恢复重复十次全部成功 |

对冲实验通过只说明这类机器能跑 PVM 下的 microVM，不说明第一版能在 CubeSandbox 上走通。

## 产出

- 拒绝的判据、总耗时的上限、已有沙箱的行为，以及由此得到的一张运行时表现到接口状态码的翻译表。
- 适配器应用容量的做法：写哪个文件、怎样校验、怎样重启、怎样回读；关闭超分的写法。
- 节点栈的部署形态，以及节点适配器装在哪里、监听在哪里。它同时回答提案的两项待决策：kuasar 的接入方式（ND-2）、节点部件怎样打包（KD-A7）。
- 运行时凭据的制备步骤和适配器要读的文件清单。
- 钉住的 kuasar 版本，以及在这个版本上对接入契约前 9 条的核对记录。
- 准备第一个可用模板的步骤。

## 不在范围内

- 修改 kuasar 的代码。
- 出站网络、暂停与恢复、运行中改容量。
- 在开发机换内核或安装运行时。
