## 目标

给会话存储加上池路径要用的字段，以及以后身份和可观测要用的字段；补上它今天没有的条件写和原子操作。现有路径的行为不变。这里说的是改动之前就有的会话路径，与总体计划 D22 说的两个后端无关。

基线的现状：写入用普通管道，不检查 `SETNX` 的结果；更新只判断键存在，没有版本号；只有到期和最后活动两个全局索引；多键操作在集群模式下会跨槽。

## 范围

1. **字段。** 按 000-1 的字段表加到会话记录上，都带 `omitempty`，并规定零值的含义。`backend` 缺省等于 `pod`。所有者在池路径上也要填。给以后才用的字段留出可选位置，旧记录可读。
2. **三个索引。** 公开沙箱标识、命名空间、池。兼容上有两种不一致要处理：
   - 索引里有、记录没有的成员。旧版本进程的删除路径不认识新索引，会留下它们。读路径要容忍，并有清理。
   - 记录有、索引里没有的成员。升级之前的存量记录，以及滚动升级期间旧进程新建的记录，都不在新索引里。

   第一版的做法是让三个新索引只覆盖池后端的会话。池会话只由新版本、在后端设为 `pool` 的部署里创建（总体计划的 D22；原先写的是“在开关打开之后”），所以不存在需要回填的存量；`pod` 部署的会话不进新索引，第一版也没有功能经新索引去列出它们。以后有功能需要按命名空间列出全部会话时，再安排回填、增量补漏和完成水位。
3. **三个原子操作。** 创建占位记录（已存在时明确失败）、状态转换（比较版本号、`generation` 和状态）、确认删除（记录和全部索引成员一起删）。Redis 和 Valkey 两个实现都要有。
4. **发件箱。** 状态转换和确认删除在同一个原子操作里追加一条发件箱条目；提供读取和确认两个方法，任一副本可以接手。条目格式按 000-1。转发方不在本子任务里。
5. **写入边界。** 会话主记录只有 WorkloadManager 写；Router 只更新最后活动时间。存储接口上不提供别的写入口。
6. **测量。** 在真实的 Redis 和 Valkey 上量创建路径多出的这次写入的耗时。这是提案实验 KE-O2 里本地持久写的部分；单测用的内存实现不代表真实行为。

## 不在范围内

- 把现有 `pod` 路径切到新的原子操作。它继续用现有方法，除非 000-8 或 000-9 的实施提案另有决定。
- 世代标记（第三版）。键名先占位。
- “不能丢”的投递等级和转发库（第四版）。
- 运行时令牌的密封与保存（第二版）。字段先留着，第一版为空。

发件箱的结构要在第一版定下来，原因是它改变的是创建、状态转换、删除三个原子操作的范围，后改等于重写它们和它们的测试。

## 验收

- 没有新字段的旧记录可读，并按 `pod` 后端处理。在 `pool` 部署里，这样的记录属于别的后端：读得出来，能被启动时的检查发现；运行期间遇到它怎样处理，按总体计划待定问题 3、4 的结论，建议是拒绝并告警、不处理。
- 两个并发的状态转换带同一个期望版本号，恰好一个成功。
- 用已存在的标识创建占位记录，明确失败。
- 确认删除之后，记录和三个新索引、两个旧索引里的成员都不在了。
- 每次状态转换恰好追加一条发件箱条目；一个副本读取、另一个副本确认可以工作。
- Redis 和 Valkey 两个实现都通过同一套用例。
- 现有的存储单测和端到端测试不改即通过。
- 新旧版本并存：旧版本的垃圾回收面对带新索引的数据不出错，新版本的列表不被无主成员卡住；不在新索引里的 `pod` 会话，现有的读取、删除和垃圾回收照常工作。
- 写入耗时的测量结果记在本子任务的实施提案里。
