## 目标

目标里要求保留身份和可观测的可扩展性。这两条线的接缝有六成落在两条路径共用的会话路径上。本子任务把它们落实：调用点、传递的内容、埋点的骨架都就位，规则等价于现状。`pool` 后端（000-10）接上来之后自动继承它们。

对外接口不变。有两处有意的变化：没有登记的操作被拒绝；Router 的访问日志改成结构化的，不再记查询串。

基线的现状：认证是可选的；授权只有一个所有者比对函数，带 `admin` 字面量旁路；没有租户；没有指标、trace、事件；日志是格式化文本。

## 范围

**身份。**

1. **主体结构。** Router 的认证中间件把认证结果统一成 000-1 定义的主体结构。认证被配置关闭时，产生一个明确的匿名主体，而不是没有主体。
2. **会话接口携带的内容。** Router 发给 WorkloadManager 的每个请求带主体、租户、策略版本（第一版是常量）和 trace 上下文。WorkloadManager 只在调用方被认证为 Router 时才信任请求里携带的主体；Python SDK 直连 WorkloadManager 时，主体取自 WorkloadManager 自己的认证结果，认证关闭时是匿名主体。
3. **操作注册表。** Router 和 WorkloadManager 的每条路由登记动作名和取资源的方式；现有路由全部登记；没登记的路由被拒绝。
4. **决策函数。** 在后端分叉之前调用，两条路径共用。决策库要能同时链接进 Router 和 WorkloadManager。第一版的规则按 D11：
   - 匿名主体照现状放行；所有者比对、`admin` 旁路保留；WorkloadManager 的删除接口不检查所有者，保留。
   - 认证开启而主体缺失或无效，拒绝。
   - 可信上下文缺失，拒绝：例如自称来自 Router 的请求没有通过 Router 的身份校验；注册表没有加载；读不到会话事实。
   - 关闭认证的部署在第一版不满足“没有主体即拒绝”，记为已知缺口。
5. **决策日志。** 每个决策一条结构化日志，字段按提案里审计记录的草图。不含凭据和请求体。
6. **令牌签发的调用点。** 创建成功之后调用访问令牌签发的桩。第一版不签发。

**可观测。**

7. **埋点骨架。** 用 OpenTelemetry SDK，同时提供 Prometheus 抓取端点和 OTLP 推送；指标前缀 `agentcube_`；基数规则用属性白名单在埋点处执行；Router 的路由标签用路由模板，不含标识。第一版的指标只做请求数与时延。
8. **trace。** 一次创建在入口开根 span，经会话接口传到 WorkloadManager，其下有授权、创建会话、写会话存储的 span；后端内部的 span 由各后端补。入站的 trace 是否延续由配置决定。创建时的 trace 上下文存进会话记录。
9. **生命周期事件。** 在状态变更处产生，带每个 `generation` 内递增的序号，经 000-7 的发件箱与状态变更同一个原子写入。第一版由一个转发协程读发件箱并写成结构化日志，尽力而为。
10. **日志与隔离。** 把 Router 现有的访问日志中间件换成结构化的，不记查询串；新代码的日志同样是结构化的。会话路径不等待任何远端的遥测端点。

## 不在范围内

- 访问令牌的签发与校验、撤销水位的前移。
- 策略对象、策略控制器、关系引擎。
- 收紧现有规则，包括去掉 `admin` 字面量、OIDC 关闭时默认拒绝、给 WorkloadManager 的删除接口加所有者检查。这些是行为变化，要单独批准，放在第二版。
- 审计通道、Collector 的部署、指标清单的补齐（第三版及以后）。

## 验收

- 现有端到端测试不改即通过；对外接口逐项对照没有变化。
- 兼容矩阵：新旧 Router 与新旧 WorkloadManager 的四种组合，乘以认证开启与关闭，再加 Python SDK 直连 WorkloadManager。每种组合下创建、调用、删除的结果与基线一致；旧 Router 不带主体的请求在新 WorkloadManager 上按 D11 处理。
- 认证开启时，不带凭据或带无效凭据的请求被拒绝；伪造主体请求头、但调用方不是 Router 的请求，主体不被采信。
- 加一条没有登记的测试路由：请求被拒绝，并留下带主体和原因的日志。
- 每个决策有一条结构化日志，其中没有凭据和请求体。
- 发一个查询串里带敏感参数的请求：Router 的访问日志是结构化的，其中没有查询串。
- 一次经 Router 的创建是一条 trace，含 Router 和 WorkloadManager 的 span；会话记录里有创建时的 trace 上下文。
- 指标端点可以抓取；逐个检查指标的标签，没有会话、沙箱、所有者这类随会话数增长的标识。
- 把遥测端点配成不可达，创建照常成功，时延没有明显变化。
- 在开发机上的 Kind 上用改动后的构建验证以上各项。
