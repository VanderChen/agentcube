## 目标

把前面的子任务装在一起，按第一版的准出标准逐条验收，并把没有做到的如实写出来。

## 范围

1. **安装。**
   - chart 的汇总：两个 CRD、两个命名空间、优先级类、池控制器、`placeholder-agent`、WorkloadManager 的开关与权限。
   - 节点一侧的安装说明：kuasar 节点栈的固定版本、节点适配器、可选的 shim。形态按 000-5 的结论。
   - 引导链路逐项写清楚，对应总体计划“第一版的引导与连接”一节：运行时凭据怎样制备和放置；适配器与 WorkloadManager 的证书由谁签、放在哪、各自校验什么身份；适配器的地址怎样发布；网络路径怎样检查；模板怎样预置。
   - 创建开关的启用、关闭和回滚规程。
   - 一份从空集群到发放第一个 microVM 的操作步骤。
2. **端到端用例。**
   - 开发机上的 Kind 加假运行时。它不需要 KVM，可以进持续集成。
   - 带 KVM 的机器加 kuasar-sandbox。
3. **准出核对。** V1-1 至 V1-7 逐条给出命令、输出和结论。
4. **接缝核对。** 身份 26 条、可观测 26 条里分给第一版的条目，逐条对应到代码位置或测试；分给后续版本的条目，确认字段或调用点已经留好。
5. **已知缺口的说明。** 至少包括：
   - 节点压力下 kubelet 驱逐谁没有验证；占位 Pod 的 requests 只是记账，内核不据此限制沙箱。
   - PodDisruptionBudget 对各驱逐路径的效力没有验证。
   - 所有节点的 `placeholder-agent` 共用一个身份，能写任何池的状态。
   - 认证与授权没有收紧；关闭认证的部署不满足“没有主体即拒绝”。
   - 经 Router 的数据面不可用；运行时令牌没有保存。
   - 只验证了单个 WorkloadManager 副本。
   - 池的大小固定，运行中不能调整；运行时的超分是关闭的。
   - 适配器重启后只恢复自己认领过的实例，未知实例只报告。
   - 运行时凭据和证书靠手工安装，没有轮换。
   - 适用范围是受控的环境，不对多租户开放（D16）。
6. **对提案的回写清单。** 实验结果与提案的假设不同的地方列成清单。提案是内部文档，不在这里改。
7. **上游。** 提案更新的草稿；子任务分支怎样整理成可评审的 PR 序列的建议。按 D12，不发布。

## 不在范围内

- 新功能。验收里发现的缺陷回到对应的子任务修。
- 发布到上游。

## 验收

- V1-1 至 V1-7 全部有证据；其中 V1-3 没有通过时，写明以档 0 准出及原因。
- 开发机上的 Kind 上的端到端用例通过；带 KVM 的机器上的端到端证据记录在 本子任务的实施提案里：集群与节点的版本、镜像的 tag 与摘要、kuasar 的版本、命令、日志、前后状态、清理。
- 另一个人照着操作步骤，能从空集群走到发放第一个 microVM。
- 已知缺口的说明经过负责人确认。
- 取用自 sandbox-pool 的文件和片段在各子任务里都有出处记录；agentcube 的 `go.mod` 不依赖 sandbox-pool 这个模块；取用的文件带 agentcube 的文件头，deepcopy 与 CRD 清单是工具生成的。
