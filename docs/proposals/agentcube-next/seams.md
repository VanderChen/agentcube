# 身份与可观测的接缝清单

第一版不交付身份（identity）和可观测（observability）这两条线的功能。本清单列出第一版必须留好的接缝：数据模型、接口签名和调用路径上要先有的形状，有了它们，以后加功能时不用返工。每一条都写成可以在代码评审或测试里检查的形式。

清单整理自内部的提案分析（内部报告 04），要求本身取自内部的设计提案。“子任务”一栏是本计划的分配：有两个以上子任务时，排在前面的负责定义，后面的负责落实；第一版集成验收（000-11）逐条核对。

文中的编号：

- `M1` 至 `M14` 是提案的模块编号，见下表。
- `IF-n` 是提案的接口编号。本清单用到的：IF-2 是 Router 到 WorkloadManager 的会话接口；IF-3 是 WorkloadManager 内部的后端接口；IF-4 是到节点适配器的节点管理接口（沙箱生命周期与池状态）；IF-5 是 `placeholder-agent` 到节点适配器的容量接口；IF-9 是授权决策；IF-9a 是访问令牌签发；IF-10a 是节点适配器到出口代理的网络键绑定。
- `KD-`、`ND-`、`PD-` 开头的是提案里待决策的编号，`OQ-` 是跨文档未决问题，`AR-` 是 agent 的运行诉求。

2026-11-25 补：本计划定了一次部署只运行一套后端（README 的 D22）。清单里“池路径和 Pod 路径共用”“两条路径”这样的说法，读作“不论这次部署启用哪个后端，都经过同一段代码”；它们不表示两个后端在同一套部署里同时运行。要求本身没有变。

## 身份

提案的主线是“签发令牌时做决策，数据路径上只验签”。

### 数据模型（会话记录）

| # | 可检查的要求 | 为以后的哪项能力留位置 | 子任务 |
|---|---|---|---|
| I-1 | 会话记录从第一版起带 `ownerId`，并且池路径上也填（今天只在原生路径上有） | 所有者规则；审计里的主体 | 000-1、000-7 |
| I-2 | 会话记录带 `namespace`（租户）、`agent`、`policyRef`、`policyVersion`，第一版可以为空或取常量 | 按 agent 的授权；策略版本进决策审计和令牌 | 000-1、000-7 |
| I-3 | 会话记录带 `revokedBefore`（撤销水位），第一版为空 | 撤销访问令牌 | 000-1、000-7 |
| I-4 | 会话记录带 `generation` 与 `rev`；`generation` 每次激活加一，由 M2 先以比较并交换写入再提交 | 令牌的 `gen` 声明；旧实例的令牌随激活失效 | 000-1、000-7 |
| I-5 | 会话记录带 `tokens`（运行时令牌的密封副本），不是摘要 | connect 要再次返回令牌；Router 换上运行时令牌转发 | 000-1、000-7 |

| I-7 | 公开沙箱标识只含小写字母和数字，并有 `sandbox:<publicSandboxId>` 索引 | 访问令牌的受众是 `sandbox/<公开沙箱标识>`；主机名路由 | 000-1、000-7 |
| I-8 | 会话主记录只有 M2 写；Router 只写活跃时间和自己的发件箱；存储接口上不提供别的写入口 | M12 的控制器以后经 M2 前移撤销水位与最低策略版本 | 000-7 |
| I-9 | 状态变更走带期望值的条件写（`Transition` 比较 `rev`、`generation`、`status`） | 撤销水位与最低策略版本“取现值与新值的较大者”的写入 | 000-7 |

| I-20 | 适配器选用运行时凭据的地方是一个按 `namespace` 取凭据的函数，第一版可以恒返回同一组 | ND-7 定为“每个命名空间一组运行时凭据”时不改调用点 | 000-6 |

关于 I-26：基线里认证关闭时所有者检查恒通过。第一版不收紧现有规则，所以关闭认证的部署不完全满足这一条，口径见 [README](README.md) 的 D11。

第一版在身份上完全不做的：访问令牌的签发与校验、撤销水位的前移；策略对象、编译器与策略控制器；沙箱身份令牌；出口代理与凭据绑定；审计通道；关系引擎、用户委托与审批；API key 与 ServiceAccount 令牌认证；guest 内的策略；去掉 `admin` 字面量旁路。

## 可观测

提案的主线是“身份只在可信一侧写入，随会话数增长的标识不进指标标签”。

基数分三类：A 类是固定枚举或运维方创建的对象（池类、池、节点、运行时、模板、agent、结果码），可以出现在所有信号里；B 类随租户数增长（租户），指标里只上计数器和量表；C 类随会话数增长（沙箱、会话、`generation`、所有者、父会话、组、批次、trace），不得作 Prometheus 标签或日志的索引标签。

| # | 可检查的要求 | 为以后的哪项能力留位置 | 子任务 |
|---|---|---|---|
| O-1 | 属性一律用保留前缀 `agentcube.*`（KD-O7 的建议），键名集中定义在一处，各组件不自己拼字符串 | “不可信来源的同名键一律丢弃”才能写成一条规则 | 000-1 |
| O-2 | 指标标签只允许 A 类；B 类（租户）只上计数器和量表，不上直方图，并有总开关；C 类（沙箱、会话、`generation`、所有者、父会话、组、批次、trace）不作 Prometheus 标签，也不作 Loki 索引标签 | 序列数与节点数成正比，与会话数无关 | 000-2、000-9 |

第一版在可观测上完全不做的：节点采集层与集群汇聚层的部署、guest 的遥测摄入、运行时遥测的转换；用量记录的产出、分摊与成本导出；查询服务、E2B 的指标与日志端点、审计存储；“不能丢”的投递等级；尾采样、沙箱内的传感、内容采集策略、录屏。
